# PlaylistPro 최종 발표자 노트

## 1. 표지

PlaylistPro의 목표는 단순히 이탈 확률을 맞히는 것이 아니라, 제한된 고객 유지 자원으로 누구를 먼저 검토할지 결정할 근거를 제공하는 것입니다. 분석·모델·운영 선택지를 하나의 흐름으로 연결했습니다.

## 2. 문제에서 의사결정까지

사용 신호를 확인하고, 모델로 위험 순위를 만든 뒤, Recall·Precision·접촉량을 비교해 운영안을 선택합니다. 앱은 후보와 가정을 제시하지만 CRM 발송, 할인 집행, 고객 접촉은 담당자가 승인해야 합니다.

## 3. 데이터와 범위

학습 데이터는 12만 5천 명, 미라벨 고객은 7만 5천 명입니다. 결측·중복·키 중복은 없었습니다. 다만 규칙 기반 합성 데이터로 판단되며 예측 horizon과 외부 라벨 Holdout이 없으므로 현실 일반화를 주장하지 않습니다.

## 4. EDA에서 전처리로

주간 이용시간, Free 요금제, 문의, 일시정지, 스킵이 주요 관찰 신호였습니다. Logistic 고정 검증에서 로그 수치 특징은 PR-AUC를 0.006798 높여 채택했고, 복잡한 비율 특징은 개선이 없어 제외했습니다.

## 5. 성능 개선 경로

각 실험의 문제 관찰, 가설, 변경 전후 지표, 채택·제외 이유를 남겼습니다. 전체 모델을 다시 학습하지 않고 기존 OOF 예측과 Run manifest를 재사용해 발표 근거를 만들었습니다.

## 6. 8개 모델 공정 비교

동일 특징, 동일 Stratified 5-Fold, 동일 평가 지표로 8개 모델을 비교했습니다. Baseline 상위는 CatBoost, LightGBM, XGBoost였고 세 모델의 차이는 매우 작았습니다.

## 7. 제한된 탐색과 정밀 튜닝

탐색 횟수 상한을 두고 상위 3개만 정밀 튜닝했습니다. Fine CV PR-AUC는 CatBoost 0.947913, LightGBM 0.947806, XGBoost 0.947793입니다. 작은 차이를 과장하지 않습니다.

## 8. CatBoost 선정

CatBoost는 순위 품질과 seed 안정성에서 근소하게 앞서 최종 위험 순위 후보로 선택했습니다. LightGBM은 기본 threshold의 Recall과 Calibration에서 장점이 있었고 Bootstrap 구간도 겹칩니다. 따라서 CatBoost를 절대적 우승 모델로 표현하지 않습니다.

## 9. Threshold 운영 시나리오

Recall 우선 0.29는 FN을 줄이지만 접촉량이 큽니다. Precision 우선 0.74는 접촉 효율이 높지만 놓치는 이탈 고객이 늘어납니다. 기본안 0.35는 OOF F1 균형점이며 실제 운영 정답은 비용과 허용 FN을 반영해 담당자가 정합니다.

## 10. Top-K, Lift, Risk Decile

상위 10%는 OOF 기준 이탈자의 19.48%를 포함하며 Lift는 1.948배입니다. 이는 제한된 인력의 1차 접촉 범위를 설명하는 지표이지 실제 캠페인 효과가 1.948배라는 뜻은 아닙니다.

## 11. Streamlit 의사결정 지원

앱에서는 위험 고객을 필터링하고 운영 단계, 1차 신호, 구독 유형별 비용·가치 가정을 함께 확인합니다. 행동 제안은 사람이 검토할 후보이며 자동 처방이나 자동 발송이 아닙니다.

## 12. 재현성과 제출 패키지

실행 완료 노트북 3개, 모델·메트릭·스키마, 보고서, 앱, 발표자료, 요구사항 추적표를 한 폴더에 구성했습니다. 모델 해시는 로드 시 검증하며 전체 모델 재학습은 하지 않았습니다.

## 13. 한계와 다음 검증

시간 기반 Holdout, 세그먼트별 오류·Calibration 재검증, 실제 캠페인 A/B 테스트, uplift·ROI 측정이 다음 우선순위입니다. 라이선스와 비용·가치 가정의 조직 승인은 사람이 확인해야 합니다.

## 14. 결론

핵심은 다섯 가지입니다. EDA와 전처리를 연결했고, 8개 모델을 공정하게 비교했으며, CatBoost를 근소한 최종 후보로 선택했습니다. Threshold와 Top-K를 운영 선택지로 만들었고, 실제 효과는 별도의 Holdout과 A/B 테스트로 검증해야 합니다.
