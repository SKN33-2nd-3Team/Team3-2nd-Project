# 요구사항 정의서

> 프로젝트 가이드 §①(비즈니스 문제 정의)의 9개 항목 정의서.
> 최종 갱신 2026-07-21 (신규 데이터셋 기준).

## 프로젝트 문장

> **음악 스트리밍 서비스의 리텐션 담당자**가 **어떤 고객에게 어떤 유지 활동을 배정할지** 결정할 수 있도록,
> **고객별 구독·이용·상담 프로필**로 **이탈 여부(`churned`)**를 예측하고 **위험 등급별 유지 활동**을 제안한다.

> 우리 팀은 **행동 가능 위험 신호 2개 이상 보유 고객군**을 집중 검토하기 위해 **이탈 Recall과 PR-AUC**를 우선 확인하고,
> 예측 결과를 **3단계 운영 흐름(집중 관리/자동화 검토/관찰 유지)**에 활용한다.

## 요구사항 표

| 항목 | 작성 내용 |
|---|---|
| **사용자** | 리텐션·CRM 담당자. Streamlit 화면에서 고객 위험도를 조회하고 캠페인 대상 목록을 내려받는다. |
| **문제** | 학습 데이터 기준 이탈률이 51.3%다. 누가 떠날지 사전에 알 수 없어 유지 예산이 전 고객에 균등 소진되고 있다. |
| **Target** | `churned` (0 = 유지, 1 = 이탈). 데이터셋이 제공한 라벨을 그대로 사용한다. |
| **예측 시점** | **미정의.** 데이터에 관측 기준일·해지일이 없다. 따라서 "스냅샷 시점의 프로필로 제공 라벨을 판별"하는 것으로 범위를 한정한다. ([validation_plan.md](validation_plan.md) §4 참조) |
| **관찰 기간** | 미정의. `signup_date`가 기준일 대비 일수(−1 ~ −2,922)로만 주어져 Feature 산출 구간을 특정할 수 없다. |
| **결과 기간** | 미정의. "향후 30일 내 해지"라는 표현은 **사용하지 않는다**. |
| **주요 지표** | 1순위 **이탈 Recall** (FN = 떠날 고객을 놓침, 비용 큼), 2순위 **PR-AUC**, 보조로 Precision·F1. Accuracy 단독 사용 금지. |
| **화면** | ① 프로젝트 요약 ② 데이터·고객 인사이트 ③ 개선 실험 ④ 모델 선정 ⑤ 운영 시나리오 ⑥ 고객 우선순위. 고객 우선순위는 단건 재추론, 유지 활동 후보, 담당자 선택, 전략 포함 배치 큐, 가정 기반 캠페인 계획을 포함한다. |
| **완료 기준** | 저장 모델이 새 프로세스에서 로드되고, 신규 고객 1명을 예측하며, Streamlit이 재학습 없이 그 모델을 호출한다. |

필수 결과 문서는 [전처리 결과서](../reports/preprocessing_report.md)와 [모델 학습 결과서](../reports/training_report.md)로 분리해 제출한다.

## FN / FP 비용 판단

- **FN (떠날 고객을 놓침)**: 고객 LTV 전액 손실. 팀 가정 LTV = 월 ARPU 10,000원 × 12개월 = **120,000원**
- **FP (남을 고객에게 캠페인)**: 캠페인 단가만 손실. 저비용 채널 기준 수천 원
- → 최종 CatBoost OOF 근거로 **재현율 우선 0.29 / 균형형 F1 0.35 / 정밀도 우선 0.74**를 비교한다. 기본 화면값은 0.35이며 최종 운영 기준은 담당자가 용량·비용을 확인해 선택한다.
- ⚠️ 위 120,000원은 Threshold 설명용 **팀 가정값**이며 실제 LTV가 아니다. 가정 기반 캠페인 화면은 이 값과 분리해 외부 공개 요금 기반의 편집 가능한 `연간 매출 대용치`와 채널 운영비 가정을 사용한다.

## 기능 범위

| 구분 | 항목 | 상태 |
|---|---|---|
| **Must** | 데이터 분석, ML 모델 비교, 저장 모델 예측, Streamlit 3화면 | ✅ 완료 |
| **Should** | 임계값 조정, Feature 해석, 고객 대응 전략 | ✅ 완료 (운영 시나리오 / 유지 전략 검토 / 가정 기반 계획) |
| **Could** | 배치 예측, CSV 다운로드 | ✅ 완료 (Batch Prioritization) |
| **Could** | DL 비교, SHAP 개별 설명 | ❌ 미착수 — [validation_plan.md](validation_plan.md) §5의 근거로 **의도적 제외** |
| **Won't** | 로그인, 얼굴 인증, 별도 React, 복잡한 DB | ❌ 범위 외 |

## 범위 제외 사항

- 외부 캠페인 자동 실행, 고객 차단, 자동 해지 통지는 포함하지 않는다. 화면 결과는 **검토 우선순위 지원용**이다.
- 예측 확률을 인과적 이탈 원인으로 제시하지 않는다. 모든 관계는 연관성이다.
- 유지 활동 후보는 예측 모델과 분리된 투명한 규칙으로 생성하며 담당자 선택 전에는 `미검토` 상태다.
- 행동 후보에는 문의 수준, 청취시간, 스킵률, 구독 일시정지, 구독 유형만 사용한다. 나이·지역·고객 ID는 모델 입력일 수 있으나 행동 배정 근거에서는 제외한다.
- 전략별 KPI는 향후 통제된 캠페인에서 검증할 측정 항목이며, 현재 앱이 실제 효과를 보장하지 않는다.
