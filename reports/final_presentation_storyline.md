# PlaylistPro 최종 발표 Storyline

## 한 문장 Storyline

> 고객 유지 자원이 제한된 문제에서 출발해 고객 행동 인사이트를 발견하고, 이를 검증 가능한 Feature와 유지 활동 가설로 바꾼 뒤, 공정한 모델 검증을 거쳐 위험 고객 우선순위와 담당자 의사결정 흐름으로 연결했다.

## 본문 14장 구성

| No. | 슬라이드가 답하는 질문 | 결론형 제목 | 서사 역할 | 다음 슬라이드 연결 |
| ---: | --- | --- | --- | --- |
| 1 | 이 프로젝트가 만든 가치는 무엇인가? | 모든 고객을 관리할 수 없다면, 먼저 검토할 고객과 행동 가설이 필요하다 | 프로젝트의 주인공을 모델이 아니라 리텐션 담당자로 설정 | 어떤 결정을 지원해야 하는가? |
| 2 | 사용자는 예측 결과로 무엇을 결정하는가? | 목표는 이탈 여부를 맞히는 것이 아니라 유지 자원을 배분하는 것이다 | 사용자·결정·FN/FP·3단계 운영 흐름 정의 | 무엇을 이용해 위험도를 판단했는가? |
| 3 | 데이터로 무엇을 예측했고 어디까지 해석할 수 있는가? | 12.5만 고객 프로필로 `churned`를 판별했지만 미래 기간과 외부 일반화는 미확인이다 | 데이터·Target·합성 판정·누수 경계 제시 | 이 범위에서 어떤 고객 신호가 관찰됐는가? |
| 4 | 어떤 고객군에서 위험이 높게 관찰됐는가? | 낮은 청취 활동·Free 구독·높은 문의가 서로 다른 이탈 위험 맥락을 보여줬다 | 핵심 인사이트 3개를 행동·상품·서비스 축으로 설명 | 관찰을 실제 행동으로 어떻게 연결할 것인가? |
| 5 | 인사이트가 어떤 유지 활동으로 연결되는가? | 위험 신호는 서비스 회복·재활성화·혜택 안내 실험 후보로 전환된다 | 프로젝트 요구사항인 ‘어떤 고객에게 어떤 행동’에 답함 | 이 가설을 모델에 어떻게 반영하고 검증했는가? |
| 6 | EDA와 모델링은 어떻게 연결됐는가? | 관찰된 비선형성과 행동 구조를 Feature 가설로 만들고 채택·제외를 기록했다 | 인사이트 → Feature Engineering 연결 | 개선을 공정하게 판단할 기준은 무엇이었는가? |
| 7 | Baseline과 평가 설계는 왜 믿을 수 있는가? | 동일 Fold와 Pipeline 내부 Fit으로 개선 원인과 누수 위험을 분리했다 | Dummy·Raw Logistic·PR-AUC·Recall·OOF 원칙 설명 | 어떤 실험이 실제 개선을 만들었는가? |
| 8 | 성능을 높이기 위해 무엇을 시도했는가? | 비율+로그 복합 변환과 비선형 모델 전환은 개선됐고 비율 단독·상호작용·일부 탐색은 제외됐다 | 강사 요구사항의 과정·논리·채택·실패 실험 제시 | 여러 모델 중 어떤 후보가 경쟁력을 보였는가? |
| 9 | 왜 CatBoost를 선택했는가? | CatBoost는 근소한 랭킹 우위와 반복 안정성으로 선정했지만 절대적 승자는 아니다 | 8개 모델·Top 3·Seed·Bootstrap·LightGBM Trade-off 통합 | 같은 모델을 어떤 운영 기준으로 사용할 것인가? |
| 10 | 임계값에 따라 운영 결과는 어떻게 달라지는가? | Recall을 높이면 놓침은 줄지만 검토 고객과 불필요한 접촉이 늘어난다 | Threshold별 대상 수·Recall·Precision·FN·FP 비교 | 인력이 먼저 정해져 있다면 어떻게 선택하는가? |
| 11 | 제한된 인력에서는 누구부터 관리해야 하는가? | Top-K는 검토 가능한 고객 수를 직접 우선순위로 바꾸는 기준이다 | Capture·Lift·Risk Decile로 모델을 의사결정에 연결 | 선정된 고객에게 어떤 행동을 검토하는가? |
| 12 | Streamlit에서 사용자는 무엇을 하는가? | Streamlit은 위험 점수·신호·행동 후보·담당자 선택을 하나의 검토 흐름으로 연결한다 | 6개 화면과 고객 우선순위·가정 기반 계획의 실제 역할 설명 | 현재 도구가 아직 답하지 못한 것은 무엇인가? |
| 13 | 무엇을 말할 수 없고 다음에 무엇을 검증해야 하는가? | 현재는 우선순위 기술 검증이며 실제 유지 효과는 미래 라벨과 A/B 테스트가 필요하다 | 합성 데이터·예측 기간·외부 Holdout·인과·공정성 한계 정리 | 그래서 프로젝트의 최종 가치는 무엇인가? |
| 14 | 이 프로젝트가 최종적으로 완성한 것은 무엇인가? | 고객 이해에서 행동 실험 대상 선정까지 하나의 의사결정 구조를 만들었다 | 최초 질문에 답하고 프로젝트 가치를 3단계로 회수 | 종료 및 Q&A |

## 이야기의 연결 고리

```text
리텐션 자원 제약
→ 고객 행동·구독·서비스 신호 발견
→ 행동 가능 신호와 진단 신호 구분
→ Feature 가설과 유지 활동 가설 생성
→ Baseline·실패 실험·8개 모델 공정 검증
→ CatBoost 위험 순위와 Threshold·Top-K 운영 기준
→ Streamlit 담당자 검토·행동 선택
→ 미래 라벨·A/B 테스트로 실제 효과 검증
```

## 본문과 질문 대응 자료의 경계

본문에는 판단에 필요한 핵심 수치만 사용한다. 다음은 발표 흐름을 끊으므로 질문이 들어왔을 때 제시한다.

- 전체 8개 모델의 모든 Metric과 추론시간
- 7개 모델의 전체 탐색 범위와 Trial 결과
- Seed별 15개 행 전체
- Calibration 세부 곡선과 기본 Threshold Confusion Matrix
- 전체 Feature 목록과 CatBoost 중요도
- 세그먼트별 오류 전체 표
- 패키지 버전과 SHA-256 재로딩 로그
